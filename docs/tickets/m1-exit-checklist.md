# Milestone 1 exit checklist

One row per requirement ID that Milestone 1 claims, with the ticket that owns it and the test that proves it. A ticket's PR description names the test for every ID it claims and updates this file (`CLAUDE.md`, Session discipline). The ticket reviewer checks the PR against this table. Rows for unmerged tickets say *named in the PR*; the ticket session fills them.

The point of the table is the last section: what Milestone 2 must find in place when Milestone 1 closes. Tickets 8-pre, 8, 8b, 9, 10a and 10b are kept in scope by that section, not by this table alone.

Test names are functions; `pkg:` gives the package under `internal/` unless stated. Where a requirement is enforced by tooling rather than a test, the row says so.

## What Milestone 2 must find in place

Milestone 2 builds the evaluation harness: the `test_writer` role and hidden-test split, a replay benchmark of at least 20 tasks from the owner's repositories plus a SWE-bench Verified subset, and a report of resolve rate, cost per resolved task and time per task, with model, prompt and configuration versions recorded and flaky tests excluded (FR-S7, FR-A2, FR-A4, NFR-P6). Each item below is a seam a Milestone 1 ticket must leave, or a deferral it must record. The ticket in brackets owns it.

1. **A task runs without GitHub** [8, in place: workflow `TestTaskWorkflowDirectly`, `TestCancelTaskWorkflowDirectly`; activity `TestRunAttemptTreeSourceNeedsNoGitHub`]. `TaskWorkflow` is a child workflow taking only serializable inputs: task ID, attempt ordinal, base SHA, repo full name and role. It performs no GitHub call and no delivery. The attempt gets its tree through `activity.TreeSource`, reading the repository from the plan body; Milestone 1's worker uses `GitHubTrees`, and the benchmark substitutes its own. The benchmark driver in `internal/eval` inserts a feature request, plan and task directly through the 8-pre store functions and starts `TaskWorkflow`. The parent `FeatureWorkflow` is the only thing that knows about issues, approval and PRs.
2. **The plan body is the frozen agent input** [8-pre, 8, in place: activity `TestAnalyzeTwice`]. `plans.body` (`activity.PlanBody`) holds the `TaskSpec`, the quarantined issue text, the `RepoProfile`, the `Constraints`, the repository (full name and numeric ID), and the SHA-256 of each loaded deploy file (`router.yaml`, `repos.yaml`, `toolchains.yaml`, `gates.yaml`, `sandboxes.yaml`, `github.yaml`). That is the "configuration" Milestone 2's results record.
3. **Provenance, usage and timing on every attempt** [8-pre `FinishAttempt`, 8]. `attempts` carries role, prompt version, actual model and provider, tokens, cost, steps, `started_at`, `finished_at`; `cost_events` are attributed to the attempt (8a). Resolve rate, cost per resolved task and time per task are one SQL query [10a, in place: `internal/store/trial_report.sql`, store `TestTrialReport`, printed by `conclave report`], so Milestone 2's generator starts from a query that exists.
4. **Install phase through the contract** [8-pre, 8, in place: activity `TestRunAttemptRoleAndInstall`]. `CreateWithInstall` is on `SandboxProvider`, and `sandboxes.yaml` holds per-repository image digest and install commands, so a Python image and `pip install` for SWE-bench are configuration, not code.
5. **Gate seams, additive** [7 done; 8 and 9 must not restructure]. Hidden tests become an overlay applied after the recorded diff and before the command gates; the flaky-test baseline is a staging of the base without the diff. Both fit ticket 7's re-stream staging without changing `gate.Input`'s existing fields. Ticket 9's rebase-and-re-gate reuses `Gate` unchanged [9, in place: `Finalize` calls `gate.Gate` with `InPlace` nil; `gate.Input` is unchanged; the new `gate.Rebase` and `Policy.CI` are additive].
6. **Role is data** [5 done; 8 in place: activity `TestRunAttemptRoleAndInstall`, `TestPrepareAttemptRefusesUnconfiguredRole`; 9 holds it for the pr_writer: activity `TestWritePullRequestUsesConfiguredRole`]. Adding `test_writer` is a `RoleSpec`, a prompt, a router route and a `repos.yaml` allowlist entry. The attempt activity takes the role as input and looks its spec up in `activity.Deps.Roles`, which the worker fills in `roles()` (`cmd/worker/main.go`); no activity code names the implementer.
7. **Trial issues seed the benchmark** [10b]. The 10 trial issues are written in the owner-section format (Task, Acceptance criteria, Hints) and saved under `docs/trials/local/` with their base SHA and outcome, so they are the first replay tasks. That directory is git-ignored, because ETS is private and Conclave is public; `docs/trials/README.md` holds the format, and Milestone 2's benchmark reads the local copy.
8. **Deliver is a leaf** [8, 9, in place: workflow `TestTaskWorkflowDirectly` asserts no delivery activity runs].
